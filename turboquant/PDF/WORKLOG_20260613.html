GPU 프로파일: DSV4는 메모리-바운드 DSV4_KERNEL_PROF

GPU op 클래스비중헤드룸
MoE expert matvec (IQ2_XS, 256 expert) + dense 어텐션 투영 (Q8_0)~52%LPDDR 한계 근처 — 융합은 런치만 절약
데이터 셔플 (CPY/CONT/GET·SET_ROWS/CONCAT)~19%진짜 헤드룸이나 구조적(각 op 작고 필요)
Flash-attention (D=512 압축 KV)~2.3%무시 — 압축 KV 설계가 잘 작동
matmul은 매 토큰 LPDDR에서 양자화 weight를 읽음 → 벽 너머는 바이트를 덜 읽는 것(품질 트레이드오프)뿐, 커널 융합이 아님. 어텐션이 2.3%인 건 압축 KV가 이미 잘 작동한다는 증거.

t/s 들쭉날쭉의 정체 23 → 16 → 19

t/s = (MTP 라운드당 수용 토큰) / (라운드 시간). 라운드 시간 ≈ 일정(~25ms, 타깃 verify GPU 지배), 라운드당 토큰이 수용률(96-100%)에 따라 1→3 출렁.
  • 수용률 변동(지배적) — 예측 쉬운 구간(리스트·흔한 구문) 수용률↑ → ~20 t/s. 새 내용(숫자·고유명사) → ~16. 문장마다 출렁 = spec decode의 본질, 버그 아님.
  • 컨텍스트 증가 드리프트 — KV 성장 → 라운드 시간 미세 증가. 256 배수 경계서 계단식 점프.
  • 지표 혼동 — 23(피크) / 16(essay 집계, 프롬프트 포함) / 19(최근 윈도우)는 분모가 다름.

핵심 교훈

  • 구현 전 측정 — #2 고위험 변경을 측정으로 사전 봉쇄. "건드렸는데 안 오르는" 함정을 데이터로 차단.
  • 그래프 빌드는 async GPU와 오버랩 = 임계경로 밖 — CPU-side 최적화(#1-#5)는 GPU-bound 디코드를 못 올림.
  • topology 변경 ≠ 비트-동일 — padded 뷰가 fp 누적 순서를 바꿈. "math unchanged"라도 bit-identical은 과한 게이트 → perplexity로 판단.
  • CI 위생: 올스톱 → 최종 빌드 fresh — in-flight 빌드 보존 금지. 좀비/큐 오염 방지.
  • merge -s ours — 우월한 fork가 업스트림 발산을 코드 0줄로 정리. 진짜 머지만 워크플로우 복구 필요.
  • 메모리-바운드는 quant/expert만이 레버 — matmul 52%가 LPDDR 벽. 커널 융합은 런치 오버헤드뿐.
