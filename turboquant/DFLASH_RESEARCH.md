## 1. What DFlash actually is (grounded)

A speculative-decoding **draft replacement**: instead of an autoregressive draft (EAGLE/NextN),
a tiny **block-diffusion drafter** predicts an entire block of γ tokens in **ONE parallel forward
pass**, conditioned on the target model's hidden states. The target verifies the block in one
batched pass and accepts the longest greedy-matching prefix → **lossless** (output = target's
greedy output exactly).

### Block diffusion drafting
- Block size **γ = 16** (10 for LLaMA-3.1; 16–32 is the sweet spot).
- Given a clean **anchor** token (the bonus token from the previous verify step), mask the next
  γ−1 positions; the drafter decodes ALL masked positions **in parallel** in a **single
  denoising step** (bidirectional attention within the block).
- Single step suffices because the target-context conditioning is so rich; more diffusion steps =
  marginal gain at linear cost. ⚠️ **OPEN GAP:** two source summaries conflict on whether the
  diffusion is **discrete masked-token** (MDLM/block-diffusion style) or **continuous
  embedding-space Gaussian** (q(xt|x0)=N(αₜ·E(x0),(1−αₜ)I), reverse εθ). The masked-token
  framing dominates the primary descriptions; the Gaussian framing is the theoretical basis.
  **Must resolve from the PDF + z-lab code before implementing** — this determines the whole
  drafter design.
- Cost insight: AR draft = γ·t_step (linear); diffusion draft = t_parallel (constant) → deeper
  (higher-quality) drafters at no latency penalty.

### Target conditioning (the secret sauce — "deep context extraction")
1. **Feature extraction:** hidden states from **5 layers uniformly sampled** (2nd layer →
   3rd-to-last) of the target.
2. **Feature fusion:** concatenate → lightweight projection → one compact "target context feature".
3. **KV injection:** inject the fused feature into the **K/V projections of EVERY draft layer**
   (vs EAGLE-3 = first layer only), cached persistently across the drafting block. So every draft
   layer attends to the full target context → "acceptance length scales with depth".

### Drafter architecture
- **5 transformer layers** (8 for Coder) — tiny.
- **Reuses the target's token embedding + LM head, FROZEN.** Only the 5 layers are trained.
- Bidirectional attention within block + attend to injected target features; no cross-block
  attention (Flex Attention during training).

### Training / distillation
- **Loss:** cross-entropy with exponentially-decaying position weight `w_k = exp(−(k−1)/γ)`
  (γ=7 for block 16) → prioritize early-token accuracy (later acceptance depends on it).
- **Data:** ~800K samples (NVIDIA Nemotron Post-Training V2 + CodeAlpaca), with responses
  **generated by the target model** (target alignment / "streak distillation"). 6 epochs.
- **Block construction:** sample an anchor from the response, mask the remaining block positions
  (matches inference where the verify bonus token is the anchor).

### Verification (anchor-point, lossless)
- Target computes logits for the whole draft block in **one batched forward pass**.
- Accept tokenwise (draft argmax vs target greedy) until first mismatch; +1 bonus token from the
  target becomes the next anchor. Greedy-lossless.
- **Acceptance length τ ≈ 6.5** (5.95–7.27) for block 16.

### Results
- Qwen3-8B (temp 0): **4.86× avg speedup**, 2.4× faster than EAGLE-3, τ≈6.5. Up to **6× lossless**,
  4.8× tok/s, >90% GPU util. SGLang B200: 5.1× @ conc 1 → 2.8× @ conc 32 (verify saturates).
  Reasoning/thinking: 4.6×, τ≈5.8.
- **Released drafters (MIT):** Qwen3/3.5/3.6 (4B–122B), Gemma-4, LLaMA-3.1-8B, Kimi, MiniMax,
  GPT-OSS. Backends: vLLM, SGLang, Transformers, MLX. **NO DeepSeek / DSV4. Training recipe NOT
  released yet ("soon"). NO llama.cpp.**

## 2. Why DFlash is THE lever for DSV4 (aligns with our 2026-06-13 measurements)

This session measured: `t/s = (tokens accepted per MTP round) / (round time)`, round ≈ **constant
~25ms dominated by the target verify GPU pass (memory-bound)**, draft ~9ms, acceptance ~96–100% but
the block is only **2–3 tokens** → ~16–20 t/s. The matmuls are at the LPDDR ceiling (kernel opts =
single-digit %). **The only lever that scales is the NUMERATOR (tokens accepted per round).**

DFlash attacks exactly that:
- Block **16, τ≈6.5 accepted/round** vs our current 2–3. The target verify of a 16-wide block costs
  ≈ the same ~25ms (memory-bound verify absorbs a wider batch nearly free — weights read once).
- The diffusion draft is **one parallel pass** (constant), not 16 sequential NextN steps.
- ⇒ ~6.5 tokens / ~25ms vs current ~2.5 / ~25ms → **~2–3× t/s on DSV4 (~40–60 t/s plausible)**.

This is the concrete realization of the "real lever" the profile pointed to. Kernel micro-opts
(#6–#14) can't beat the memory wall; DFlash changes the draft to widen the accepted block, which
the memory-bound verify swallows cheaply.

## 3. Mapping to our existing TurboQuant/DSV4 MTP infra

| DFlash component | Our current state | Gap |
|---|---|---|
| Target verifies draft block in 1 batched pass, accept longest prefix + bonus | ✅ `--spec-type draft-mtp` does exactly this | reuse as-is |
| Draft conditioned on target hidden state | ◐ MTP NextN head consumes full HC state (`n_embd_h=16384`, `llama_model_n_embd_h`) | single-state; DFlash wants 5-layer fusion + KV-injection into every draft layer |
| Draft mechanism | ❌ autoregressive NextN head (1 token × K sequential) | **replace with block-diffusion drafter (16 in 1 parallel pass)** — the core change |
| Drafter reuses target embd + LM head | partial (NextN reuses some) | align |
| Anchor-point greedy-lossless acceptance | ✅ our spec accept logic | reuse |

So the **verify path is reusable**; the **draft path (NextN AR → block diffusion) + the richer
conditioning (1 state → 5-layer fusion + per-layer KV injection)** are the real work.

## 4. Honest blockers (for DSV4 specifically)

1. 🔴 **No DSV4 DFlash drafter checkpoint.** Released only for Qwen/Gemma/LLaMA/Kimi/MiniMax/GPT-OSS.
   DSV4-Flash is exotic (MLA D=512, compressed-KV SWA+HCA, 256-expert MoE, hyper-connections). Must
   **train a DSV4 drafter** — an ML training project, not just code.
2. 🔴 **Training recipe not public yet ("soon").** The paper gives the outline (5-layer drafter,
   frozen embd+head, exp-decay loss, target-generated data, anchor masking, Flex Attention) —
   enough to ATTEMPT reconstruction, but reproducing it for DSV4 needs: DSV4-generated response
   data, the block-diffusion training loop, and training compute.
3. 🔴 **No llama.cpp integration.** DFlash is PyTorch (vLLM/SGLang/Transformers/MLX). TurboQuant is
   C++/CUDA llama.cpp → must **port** the block-diffusion drafter + KV-injection conditioning +
   anchor verify into our C++/CUDA, using z-lab's MIT PyTorch as the numerics reference (same play
   as porting DSV4 from ds4/DwarfStar). New ggml ops likely needed for the parallel-block denoiser.
